# Kit M0: findings

M0 built three Kit components in Teal on a Rust host: a toolbar of buttons, a
virtual table and a trace waterfall, all painted by the Ledger skin. Every
budget in the brief is met in Lua with no core change. The spike also turned
up one requirement the draft ADRs did not have: **large data needs a
retained channel into an extension.** Measured on 2026-10-25 on the dev Mac,
on AC power: `cargo bench -p kui-lua --bench kit`, a whole 1280×820 host frame
including layout and emission.

## Numbers

What one more button costs, the slope between frames of 0 and 200 buttons
(`buttons` rows; the frame around them is the 0 row). An earlier version
of this note divided a 20-button frame by 20 and called it 2 µs per
replayed instance, which counted the frame around the buttons too.

| Button placement | Per button | Against native |
| --- | --- | --- |
| kui's stock button from Rust, no Kit (the floor) | 0.70 µs | 1× |
| Kit slot, replayed, its params kept by the host | 1.03 µs | 1.5× |
| Kit slot, replayed, its params built every frame | 1.25 µs | 1.8× |
| Kit button inside one fill (Lua builds it every frame) | 5.95 µs | 8.5× |
| Kit slot, fresh | 29.9 µs | 43× |
| An empty Kit fill (nothing drawn: the `env` alone) | about 22 µs | — |

| Scenario | Median frame | Budget | Verdict |
| --- | --- | --- | --- |
| Table, 100,000 rows, still | 0.91 ms | 1.5 ms | met |
| Table, 100,000 rows, scrolling 37 px a frame | 1.26 ms | 1.5 ms | met, 16% headroom |

The table and waterfall frames include a five-button toolbar fill (about
45 µs).

## What the numbers say about the ADRs

1. **ADR B, decision 4 (cheap instances) is needed, and replay alone is not
   enough.** A fresh fill costs about 22 µs before it draws anything (the
   `env` with its closures), so a fresh slot is 43× a native button. A
   replayed one is 1.5× native with kept params, 1.8× with params rebuilt.
   Profiling 200 replayed slots (`--bench replay_only`) shows where the gap
   goes, in core, not in Lua:
    - **`Core::begin_slot` is O(n) per slot, O(n²) per frame.** Its
      `duplicate-slot` check scans every slot declared so far with a string
      compare (`LabelIndex::find`). It's the single hottest function at 200
      slots, and per-instance cost rises with the count (0.86 µs per button
      from 0 to 20, 1.05 µs from 20 to 200). A hash set of the frame's slot
      names makes it O(1).
    - **Each replay re-inserts its kept fill into a map** (`Kept::insert`)
      and clones every journaled `NodeSpec`, where the kept fill could stay
      in place and be pushed by reference.
    - **Each replay compares the whole `Theme` by value** (`Theme::eq`). A
      generation number checked once per frame would do it.
    - **The host's share is 0.22 µs:** a `format!` name and a params map
      every frame. Position-keyed instances (decision 1) remove the name.
   With those, a replayed instance should land at native cost. Filed for
   M2 as backlog C62 (the slot scan), C63 (re-keeping and cloning), C64
   (the palette compare) and C65 (the per-fill `env`). The bigger
   cost is a fresh one: 5.95 µs per button built in Lua, and 22 µs per
   fill. A shared `env` takes out the 22 µs; what Lua costs per node is the
   walk's (about 1 µs a table), which only less building reduces.
2. **No generic core primitive is needed yet.** The heavy components fit in
   Lua. The waterfall's levels (each merging bars under the last one's
   threshold, built once on handover) bound its cost by the width, not the
   bar count. The table's headroom is the thinnest at 16%, so watch it as
   columns grow.
3. **New: a retained data channel.** Params are declared every frame, so the
   spike sends the rows and bars once by revision (`data = { rev, rows }`,
   then `{ rev }`). That works, but the one conversion of 100,000 rows and
   18,000 bars into Lua tables takes 110 ms, a frame-sized hitch every time
   the data changes. Drafted as ADR G in Kit's plan, a **data channel**
   that the runner's workers share as their transport for bulk results. It
   takes both shapes:
    - a **dataset the host hands over by handle**, read by index from the
      script without converting the whole of it, so a 100,000-row change
      costs the rows that are drawn;
    - a **range event** from a scroll container (its visible slice changed),
      so a component can ask its host for a page of an unbounded source.
      Today an extension can reply only from `on_event`, and scrolling emits
      no event.
4. **ADR B, decision 3 (declared messages): the shape is confirmed.** The
   host passes its own `derive(Message)` values in the params, the script
   replies with a copy that has the event's fields merged in, and
   `ev.message::<Msg>()` decodes it like any stock control's message. Core
   doing this removes the messages from every frame's params and gives the
   other bindings the same typing.
5. **ADR B, decision 2 (host children) is still needed.** Buttons as data in
   the toolbar's params cover buttons and nothing else; a panel or dialog
   holding the host's own content has no workaround.
6. **ADR A, decision 3 is concrete now.** `LuaExtension::from_file` names
   the chunk by its file name alone, and a script has no `debug` library, so
   Kit cannot find its own folder. The host prepends a `package.path` line.
   ADR A should load a file with the chunk named `@<path>` and its folder
   first on `package.path`.
7. **ADR C (theme pair) shows on screen.** The host paints its background
   from the theme, and Kit paints from its tokens, so the host's
   blue-grey background sits around Ledger's paper. A skin that sets the
   theme pair closes that gap.

## Smaller findings

- **Token names need a kind-aware scheme.** The colour role `rule` and the
  rule-width length both lowered to `kitRule`, and core's `unknown-token`
  warning ("a length token, and this slot takes a color") caught it on the
  first run. Lengths now end in their unit of meaning (`kitRuleW`).
- **Core's diagnostics did a review's job.** `control-without-name` caught
  waterfall bars too narrow for their text, which had a click and no name.
  Every bar now carries a `label`.
- **Teal against `kui.d.tl` worked as is.** Props, `env`, `slot` and events
  type-check. One snag: a Teal `enum` is a type only, so a module cannot
  export it as a value (`skin.Density` read nil at run time). Use string
  literals at the boundary.
- **The build needs nothing new.** `build.lua` runs the Teal compiler kui-lua
  already vendors on any Lua 5.4+. M3 should wire `build.lua --check` into
  `scripts/gen.nu --check`.
- **Tokens declared from inside a fill work.** The settings slot re-declares
  the skin's tokens when shadows or density change, and the next frame
  paints with them.
